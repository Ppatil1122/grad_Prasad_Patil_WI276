The issue is that the `rollNo` (Primary Key) is being passed as `null` to the PostgreSQL database, which violates the `NOT NULL` constraint. While the H2 database seems to handle this (likely due to implicit auto-generation or lenient configuration), PostgreSQL is strict.

To resolve this and ensure consistent behavior across both databases, we should explicitly configure the `Student` entity to auto-generate the `rollNo`. This is a standard practice and eliminates the need for the user to manually enter a unique Roll No, avoiding collisions and null errors.

Here is the plan:

1.  **Modify `Student.java`**:
    *   Add `@GeneratedValue(strategy = GenerationType.SEQUENCE)` to the `rollNo` field.
    *   This ensures that both H2 and PostgreSQL will generate a unique ID for each new student.
    *   We will use `SEQUENCE` strategy as it is widely supported and safe for existing tables.

2.  **Modify `student.html`**:
    *   Remove the `Roll No` input field from the form, as the ID will now be generated automatically by the system.

This approach fixes the `DataIntegrityViolationException` by ensuring `rollNo` is never null.

### Proposed Changes

#### 1. Entity Update: `Student.java`
```java
// Add imports
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.SequenceGenerator;

// Update rollNo field
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "student_seq")
@SequenceGenerator(name = "student_seq", sequenceName = "student_seq", allocationSize = 1)
private Integer rollNo;
```

#### 2. Template Update: `student.html`
*   Remove the `<div class="form-group">...<label for="rollNo">...</div>` block.
